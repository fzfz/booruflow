# トラブルシューティング

各項目は症状、確認、操作、成功判定、提出情報の順です。

- **Node/npm/Git または PATH:** 欠落、非対応、実行失敗が表示されます。3 つの `--version` を確認し、表示された公式サイトから必要なバージョンを導入して、新しい端末で再実行します。`check` の成功を判定基準にします。失敗時は OS、CPU、出力、導入方法を提出します。
- **リポジトリの複製またはネットワーク:** `git ls-remote https://github.com/fzfz/booruflow.git` を確認し、回線、プロキシ、タグを修正します。スクリプトが示す未完了の出力先だけを整理して再実行します。タグのチェックアウト成功を判定基準にします。URL、タグ、Git の出力、ディレクトリの状態を提出します。
- **インストール先の競合:** 空のディレクトリを選び、既存の BooruFlow には更新スクリプトを使います。インストール概要の成功を判定基準にします。匿名化したパスと一覧を提出します。
- **`npm ci` の失敗:** Node.js のバージョン、書き込み権限、ネットワークを修正し、インストーラーを再実行します。`check` の成功を判定基準にします。Node.js と npm のバージョン、およびエラー全文を提出します。
- **ポート競合:** `status` で対象を確認して停止するか、`.env` を未使用のポートへ変更します。2 つのポートに対する `status` の成功を判定基準にします。ポート、`status`、`start` の出力を提出します。
- **設定不足:** [設定](configuration.md)の 6 変数を入力して再起動します。`check` の成功を判定基準にします。機密値を例示値へ置き換えたうえで、変数名を提出します。
- **ベクトルサービス:** URL、モデル、認証、サービスログを確認し、入力ごとに 1,024 次元であることを確認します。再試行成功が判定です。段階、種類、元 ID、秘匿済み応答を提出します。
- **画像欠落:** 詳細画面の記録、メディアファイル、`data/` の権限を確認し、画像を再追加するか、一致するバックアップから復元します。縮小画像と元画像が表示されることを判定基準にします。リソース ID、画面、要求エラー、相対パスを提出します。
- **更新失敗:** 停止状態とバックアップを保持し、表示されたローカル変更、バージョン、依存関係、移行、稼働確認の問題を修正するか、復元を実行します。`check` の成功、起動、バージョン表示を判定基準にします。移行元と移行先のバージョン、失敗した段階、バックアップ ID を提出します。
- **対象データベースが空ではない:** 新しく初期化した空のデータベースを使います。`--check` の成功を判定基準にします。テーブル名、件数、データベースのバージョンを提出します。
- **パッケージ検証:** 指摘されたファイル、形式、バージョン、参照、メディア、パスを修正し、停止済みの移行元から再度エクスポートしてパッケージを作成します。`--check` の終了コードが 0 であることを判定基準にします。形式、対象、相対パス、出力を提出します。

解決しない場合は[サポート](../community/support.md)から該当テンプレートを選びます。
