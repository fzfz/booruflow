# テスト

`npm ci` の実行後、専用ポート、一時データベース、固定されたテストデータを使います。自動テストは、本番データベース、実際の認証情報、実際の外部サイト、実際のモデルサービスから分離して実行します。

主なコマンドは `npm run test:unit`、`npm run test:contract`、`npm run test:integration`、`npm run test:migration`、`npm run test:native`、`npm run test:e2e:files`、`npm test` です。`npm run check:test-boundaries` は静的テスト境界を確認し、`npm run check:test-markdown` は Markdown を構造化データとして使っていないことを確認します。最初に影響を受けるテスト層を実行し、変更が安定した後に全テストを実行します。

契約テストは Schema、OpenAPI、エラー、移行、経路を検証します。単体テストは処理の分岐を検証し、結合テストは構成要素の組み合わせとトランザクションを検証し、E2E テストは画面上の動作を検証します。プラットフォーム用スクリプトについては、Windows x64 と macOS arm64/x64 でインストール、起動、停止、更新、復元、相互移行を確認します。新しい動作のテストは、正常、異常、境界の各条件を対象にします。

品質基準は行カバレッジ 85% 以上、分岐カバレッジ 80% 以上であり、トランザクション、メディア復旧、クエリクライアントの重要分岐は 100% を満たします。失敗時はコマンド、終了コード、最初の関連エラー、テスト層、成果物のパスを保存し、原因を修正してから影響を受ける検査を再実行します。CI は各実行の結果と成果物を保存します。

上記のカバレッジ比率は開発の受け入れ要件です。現在の CI はテストジョブの終了結果で判定し、その比率を自動計算していません。管理者は PR にカバレッジの証拠を添えます。マージと公開の制御は [CI/CD ゲート](ci-cd.md)を参照してください。
