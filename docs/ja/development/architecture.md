# アーキテクチャ

BooruFlow はローカルで動作する Node.js アプリケーションです。`app/server` は公開用と内部用のリスナーを作成し、`app/http` は画面、メディア、Catalog、Source へのリクエストを各経路へ割り当てます。`app/catalog` と各リソースモジュールは業務規則と SQLite へのアクセスを担当します。`app/vector` は 6 種類のリソースから意味検索用テキストを作り、Embedding と Reranker を呼び出してベクトルを管理します。`app/data-package` はデータパッケージを処理し、`app/maintenance` はバックアップと復旧を処理します。`app/web` は現在の中国語ユーザーインターフェースを保持します。

`schema/` はデータベース、HTTP、エラー、データパッケージの機械可読な唯一の情報源です。`config/` は実行時の既定値とリリース情報を保存します。`bin/` のプラットフォーム用スクリプトはインストールと日常運用を構成し、`scripts/` はアプリケーションの決定的な処理入口を保存します。`tests/` は単体、契約、統合、E2E の各テストを分離します。

作品はキャラクターを含みます。画風と Prompt Tag は検索可能な説明リソースです。ベースモデルはモデル、LoRA、画風、テンプレートを分類し、LoRA はモデルに関連します。アーティストプロンプト列は画風に関連付けることができます。ComfyUI インスタンスは接続情報を提供し、テンプレートは Workflow を保存します。メディア記録はリソースから分離され、カバーは順序付き画像を参照します。データパッケージのトランザクションは、業務データ、関連、メディア、6 種類のベクトル、KNN インデックスを一括して処理します。

フィールドやインターフェースを追加する場合は、先に[機械契約](contracts.md)を変更します。個別リソースの動作は対応するサービスとリポジトリに置き、複数リソースにまたがる不変条件はその規則を所有するサービスに置きます。HTTP 層はプロトコルの対応付けを行い、共有構造は Schema または構造化設定から読みます。
