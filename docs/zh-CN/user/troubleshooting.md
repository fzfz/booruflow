# 排错

每项按症状、检查、操作、成功判定和求助材料排列。

## 安装工具或网络

- **Node/npm/Git 缺失或 PATH 异常：** 脚本显示缺失、版本不支持或命令失败。运行 `node --version`、`npm --version`、`git --version`；从脚本列出的官方入口安装所需版本，重开终端并重跑安装。三个命令和 `check` 均通过即成功。仍失败时提交系统架构、命令输出与安装方式。
- **clone 或网络失败：** 安装停在仓库或标签获取。运行 `git ls-remote https://github.com/fzfz/booruflow.git`；修复网络、代理或标签输入，清理脚本报告的未完成目录后重跑。目标标签成功检出即成功。仍失败时提交 URL、标签、Git 输出和目录状态。
- **安装目录冲突：** 脚本报告非空目录。选择空目录；已有 BooruFlow 使用更新脚本。安装摘要显示目标目录即成功。仍失败时提交输入路径和目录文件列表，使用示例路径替换个人路径。
- **`npm ci` 失败：** 安装停在依赖阶段。记录 npm 输出并确认 Node 版本与写入权限；修复 Node/npm 或网络后在应用目录重跑安装。依赖安装和检查通过即成功。仍失败时提交 Node/npm 版本与完整错误。

## 启动与内容

- **端口占用：** 启动指出公共或内部端口被占用。运行状态脚本，停止对应实例或在 `.env` 选择未占用端口，再重启。状态显示两个预期端口即成功。仍失败时提交端口值、状态和启动输出。
- **配置不完整：** 检查列出 Embedding 或 Reranker 变量。按[配置指南](configuration.md)填写六项并重启。检查通过即成功。仍失败时提交缺失变量名，使用示例值替换密钥。
- **向量服务失败：** 搜索或导入报告超时、服务错误、数量或维度不符。核对地址、模型、认证和服务日志；确认 Embedding 返回每条输入对应的 1,024 维向量。重试检查或导入成功即修复。仍失败时提交阶段、资源类型、来源 ID 和已隐藏凭据的响应摘要。
- **图片缺失：** 卡片或详情无图。打开资源详情核对图片记录和文件，检查 `data/` 媒体目录权限；重新添加缺失图片或从匹配备份恢复。缩略图和原图均可打开即成功。仍失败时提交资源 ID、页面、请求错误和缺失相对路径。

## 更新与数据包

- **更新失败：** 脚本报告本地修改、版本、依赖、迁移或健康检查错误。保持应用停止，保留输出中的备份，按具体提示修复或执行恢复脚本。恢复后检查、启动和版本显示正常即成功。仍失败时提交来源/目标版本、失败阶段和备份标识。
- **目标数据库非空：** 导入列出非空表与数量。改用新安装的空数据库；不要删除单表来绕过检查。`--check` 通过空库检查即成功。仍失败时提交表名、数量和数据库版本。
- **数据包校验失败：** 命令报告缺失文件、格式、版本、引用、媒体或路径错误。重新从已停止的来源应用导出并打包，确保归档未截断。`--check` 返回零即成功。仍失败时提交包格式版本、失败对象、文件相对路径和检查输出。

仍未解决时按[求助流程](../community/support.md)选择支持或 Bug 模板。
