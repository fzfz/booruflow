# Pull Request 规范

PR 作者必须说明具体问题、修改后的行为、关联 Issue、修改范围、验证命令及结果。涉及界面时附实际截图；涉及配置、数据结构或用户操作时同步四语文档。作者可以使用任一支持语言，并按对应 `.github/PULL_REQUEST_TEMPLATE/` 模板提交。

提交后先处理自动检查。维护者先判断范围、Issue 目标和验证证据，再审阅实现。新增行为必须覆盖正常、异常和边界分支；Schema、OpenAPI、错误目录、迁移或脚本变更必须通过对应合同和跨平台检查。作者用后续提交处理意见，并在讨论中说明修改位置和复测结果。

合并条件是范围明确、实现符合机器契约、必需测试通过、文档同步、截图或操作证据齐全且审阅意见已解决。维护者在无法合并时写明具体缺口；作者补齐后重新请求审阅。
