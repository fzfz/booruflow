# 界面交互规范

本文件是所有页面的公共交互规则。页面规范必须引用本文件，并声明公共规则优先；页面文件只定义页面实际元素、布局、动作与接口映射、专属状态和验收动作。页面规则出现冲突时，开发者必须先修正页面规则。

## 1. 统一名词

可点击元素指 `button`、`a` 和具有明确键盘行为的选择项。一次请求动作对应一个用户意图和一次 HTTP 请求。进行中表示请求已发出但没有可用响应；成功要求 HTTP 状态符合契约且 `ok:true`；失败包括非成功状态、`ok:false`、非法响应、网络中断和本地取消。选中态表示页面已采用对象，草稿态只存在于前端，当前对象在请求结束前必须保持身份不变。

## 2. UI 呈现

`idle` 可发起一次动作；`disabled` 必须同时设置原生 `disabled`、禁用视觉和对应 ARIA 状态，并阻止鼠标、键盘与请求；进行中显示对象和动作、保持原内容并禁用重复提交；`selected` 必须同时设置 `.is-selected` 视觉与适用的 `aria-selected` 或 `aria-pressed`；成功只用响应数据更新内容并短暂提示；失败保留最近成功内容并显示具体原因。文案、颜色、禁用属性和 ARIA 必须同步。按钮文字变化不得造成布局跳动，失败恢复时必须保留输入、选择和滚动位置。

## 3. 按钮、点击与请求锁

动作使用真实 `button`，跳转使用 `a`；每个动作只有一个事件入口，并用 `event.target.closest('[data-action]')` 识别目标。鼠标、Enter、Space 共用同一动作和请求锁，按钮空白、文字、图标只触发一次。危险动作先打开确认层，只有确认按钮发请求；取消、关闭、返回和遮罩点击不发业务写请求。

每个发送业务请求的异步处理函数保存独立 `isSubmitting`。处理函数先校验目标，再检查锁；锁定时直接返回。未锁定时立即置 `true` 并禁用按钮，然后发送一次请求。成功时用响应更新页面；超时、网络、后端、解析或其他终止错误时显示具体错误。处理函数在成功或失败的所有终止路径都把 `isSubmitting` 恢复为 `false`，并按当前页面状态恢复仍然存在的按钮；页面跳转已经移除按钮时只释放处理函数持有的锁。前端不自动重试，用户在请求结束后每次主动重试只发送一次。纯 UI 动作为 0 次请求；单次读取、创建、更新、删除、批量、明确搜索和一批文件上传在成功或失败路径均为 1 次请求。输入、删除或清空搜索文字不得自动搜索，一个批量意图不得拆成多次单项请求。

## 4. 选中、取消与排序

前端在合法性检查后立即更新选择和视觉；同一 `kind:id` 只保留一份，提交时发送完整集合。`selection_order` 从 0 连续递增，不得跳号、为负或重复。达到上限时禁用新增并显示上限。取消按钮包含对象名称或 `aria-label="移除{名称}"`，关闭面板保留选择。

`kind` 只取 `work`、`character`、`style` 中接口允许的子集；`id` 为最小 1 的安全正整数；`selection_order` 为 0–29。作品最多 5 个、角色 20 个、画风 10 个、总数 30 个。后端必须再次校验完整集合、存在性、可用性和类型。

## 5. 前端数据校验

用户文本保存验证后的原始业务值，不转为或反转 HTML 实体。纯文本使用 `textContent`；固定 `innerHTML` 模板中的动态文本必须按上下文转义。长度按契约并在要求时按 Unicode code point 计算；空白使用 Unicode 规则。搜索词去首尾空白并把连续空白压为一个，空搜索不发请求。

资源 ID 和图片 ID 必须是安全正整数；路径 ID 的原始文本必须先满足 `^[1-9][0-9]*$`，转换后满足 `Number.isSafeInteger(value)` 和契约上限，并拒绝小数、负数、空值、科学计数法和额外片段。数字字段发送数字，拒绝 `NaN`、`Infinity`、浮点 ID 和超安全范围。请求对象必须具有所有必填字段且没有未知字段；只有契约允许时发送 `null`，不序列化 `undefined`，逐个校验数组元素。Repository 使用 SQLite 参数绑定；动态排序把已验证枚举映射到固定 SQL 片段。

## 6. 后端合法性

后端依次检查方法与路径、`Content-Type`、JSON、普通对象、缺失/未知字段、类型/长度/枚举/范围、数组重复/跳号/超量、路径 ID、对象存在/类型/可用性和完整选择集合。全部通过后才写数据库或调用媒体、向量与 ComfyUI。path、query、header、cookie、JSON 和 multipart 全部是不可信输入。

用户内容只按契约验证和规范化，不猜测或补写；操作意图必须验证范围、唯一性、归属、关系和状态；权限、owner、状态、计数、`attempt_no` 与时间由服务端取得，公开写请求不得提供。`impact_token` 等服务端签发值只能在 OpenAPI 定义的用途回传，并重新核对存在性、归属、用途和当前状态；仅在契约声明时检查有效期或一次性消费。

## 7. 请求与响应生命周期

请求前读取并校验当前表单，再按第 3 节加锁和禁用按钮。请求中保留原内容，把提交值保存在局部变量，同一对象修改按钮禁用而无关区域可用；一个请求只显示一个加载态。弹层可关闭，但关闭不取消已发出的业务请求。成功后仅以同一响应更新实体、列表、计数、选择和文案，并显示 2–3 秒成功提示；锁与控件按第 3 节恢复。缺少契约字段按结构错误处理。失败时保留最近成功数据和输入，删除临时加载、选择与排序，按 `error.code` 决定位置和重试；失败响应不得写入猜测的标题、排序、封面或列表。

## 8. 统一错误处理

错误码和文案来自 `schema/api/error-catalog.json` 及页面规则。每个错误必须说明发生结果、受影响字段/按钮/记录/文件/列表、下一步动作及当前数据是否保留。错误显示在所属区域，原始码可放折叠详情；页面不得只显示 `Error`、状态码、`undefined` 或空白。

## 9. 响应结构与一致性

JSON 使用 `{"ok":true,"request_id":"...","data":{}}` 或 `{"ok":false,"request_id":"...","error":{"code":"...","message":"..."}}`。`request_id` 由后端生成，只用于本次请求与日志关联；前端不得生成或当作任务 ID、防重入 token、幂等键。前端依次验证 HTTP 状态、JSON、`ok` 布尔值与状态一致、非空 `request_id`、成功 `data` 或失败 `error.code/message` 的契约结构。

## 10. 用户可操作的错误

字段错误显示在字段下方，使用稳定 ID、`aria-invalid` 和 `aria-describedby`，修正后立即移除且不清空输入。列表项、面板和权限错误持续显示到解决；网络状态提示可在 3 秒后隐藏，但操作附近的错误保留；未知系统错误条可在 5 秒后隐藏，日志区域保留记录。Toast 只能补充。请求失败先移除 loading、恢复允许重试的控件和数据，再映射错误并提供下一步按钮，同时记录操作、对象键和时间。`VALIDATION_ERROR` 引导修正字段，`ITEM_UNAVAILABLE` 标记失效项并重新选择，`NOT_FOUND` 返回列表，`WRITE_FORBIDDEN` 禁用写操作，`DATABASE_BUSY` 允许用户稍后手动重试，`UPLOAD_TOO_LARGE` 和 `UPLOAD_TYPE_UNSUPPORTED` 指明文件名及限制，`INTERNAL_ERROR` 保留当前数据并允许稍后手动重试。

批量操作逐项列出成功与失败，成功项保持成功，失败项保留原因；重试只提交失败项。失败后的焦点移动统一按第 12 节处理。全局错误使用 `role="alert"`，普通成功使用 `role="status"`，同一错误更新原节点。折叠详情可显示错误码、操作与客户端时间，不在主区域展示堆栈。

## 11. 并发请求

同一对象的同一动作串行执行。不同对象可以由独立异步处理函数并行处理，每个函数只更新自己绑定的区域。旧请求晚返回时不得覆盖新的当前对象或列表。

## 12. 焦点、键盘与滚动

首次加载聚焦第一个主要操作或输入。打开弹层后聚焦关闭按钮或第一个控件，锁定背景滚动；Esc 只关闭最上层，确认层优先；关闭后焦点返回打开按钮并恢复原滚动。Tab 只进入可见可操作控件。搜索更新后保留搜索框焦点，选择后保留滚动位置。字段校验错误聚焦首个错误字段；其他请求失败聚焦当前可用的重试、重新加载或原触发控件；错误没有可用操作控件时聚焦错误区域。

## 13. 加载、空数据与失败

每个数据区分别实现加载、有数据、空数据和加载失败。加载时显示骨架或文字并禁用改变同一数据的动作；空状态说明原因和下一步；失败说明原因并提供“重新加载”。局部失败只替换局部。用户点击重新加载只发送一次 GET，结束前重复点击无效。

## 14. 文件上传

选择至少一个文件后，前端先按 `config/defaults.json` 中 `uploads.allowed_media_types`、`uploads.max_file_bytes` 和 `uploads.max_files_per_request` 的当前值校验类型、单文件大小和批次数量，再显示列表。不合法文件显示名称和原因，合法文件可继续。一次点击只发送一个 multipart 请求，进行中禁用同批上传。成功以服务端图片 ID 和顺序刷新；失败保留原图库且不伪造 ID。排序用完整 `image_ids` 数组执行一次 PUT；封面使用明确 `image_id` 或契约允许的 `null`。

## 15. 状态钩子

HTML 使用 `[data-action]` 标识动作，`data-item`、`data-image-id` 等标识对象，`aria-busy` 或固定节点标识加载，`role="alert"`/`aria-describedby` 标识错误，`role="status"` 标识成功和进行中。选中和禁用状态的视觉、原生属性及 ARIA 同步统一按第 2 节处理。

## 16. 分支验收

每页必须实际验证：空值产生 0 个请求；合法值的方法、路径、请求体和次数正确；双击只有一个请求/加载/更新；鼠标、Enter、Space 产生同一动作；失败保留数据/输入/选择并恢复按钮；成功使用响应数据；晚到旧响应不覆盖新状态；非法类型、越界数字、未知字段和重复数组项返回 `422 VALIDATION_ERROR` 且无写入或上游调用；权限、找不到和不可用错误位置正确；在 390×812、768×1024、1440×900 检查焦点、滚动、抽屉、半屏面板和固定输入区。

## 17. 实现依据

HTTP 方法、路径、请求和响应以 `schema/api/openapi.yaml` 为准，错误以 `schema/api/error-catalog.json` 为准，上传限制以 `config/defaults.json` 为准。页面专属文件引用本规范并只增加页面事实。后端输入校验由当前实现和测试证明。
