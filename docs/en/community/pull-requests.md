# Pull requests

Authors must describe the concrete problem, resulting behavior, related issue, scope, verification commands, and results. Include real screenshots for UI changes. Update all language docs for configuration, data structure, or user-operation changes. Any supported language may be used with its template.

Resolve automated checks first. Maintainers assess scope, issue goal, and evidence before implementation details. New behavior must cover normal, error, and boundary branches; Schema, OpenAPI, error-catalog, migration, and script changes need their contract and platform checks. Address review with follow-up commits and report the location and retest result.

Merge requires clear scope, implementation matching machine contracts, passing required tests, synchronized docs, necessary screenshots or operational evidence, and resolved review threads. A maintainer lists concrete gaps when the PR cannot merge; the author fills them and requests review again.
